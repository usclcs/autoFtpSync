## 1. 引言

### 1.1 背景与目标

用户需要将本地文件/文件夹自动同步到 FTP 服务器。核心诉求是**免人工干预**：文件一变化，服务器端立即获得最新版本，用于静态资源发布、程序部署、素材备份等场景。

本项目为一款 Windows 桌面应用（Qt Widgets），**单向上传**（本地 → FTP），以**实时监控**为主要触发方式。

### 1.2 范围

- 范围内：本地文件/文件夹新增、修改的自动上传；服务器目录自动创建；失败重试；任务与服务器配置管理。
- 范围外：双向同步、下载同步、FTPS/SFTP、文件内容级差异同步。

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 同步任务（Task） | 一条「本地目录 + 服务器目录 + 服务器连接」的绑定关系 |
| 去抖（Debounce） | 将短时间内重复的文件事件合并为一次处理 |
| 事件（Event） | 文件系统监听产生的 新增/修改/删除/重命名 通知 |

## 2. 总体设计

### 2.1 技术选型

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Qt 5.14.2 Widgets（当前工程） | 单窗口桌面应用，Qt 自带文件系统监听与网络能力 |
| 编译 | MinGW 32-bit（当前工程） | 与现有工程一致 |
| FTP 客户端 | QNetworkAccessManager（`ftp://`） | Qt 5.14 内置支持 FTP 的 GET/PUT/DELETE/LIST，无需第三方库 |
| 文件监听 | QFileSystemWatcher | 监听目录创建/删除/重命名，再结合 `QDir::entryList` 轮询补齐文件级修改事件（见 4.3） |
| 配置存储 | QSettings（INI 文件，程序目录） | 简单可靠，便于用户迁移 |
| 线程模型 | 每任务独立上传工作线程 | 传输不阻塞 UI 线程 |

### 2.2 模块划分

```
┌──────────────────────────────────────────────────────────────┐
│                       UI 层（MainWindow）                     │
│  服务器配置页 │ 任务管理页 │ 日志/状态区                        │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│                    任务调度器（TaskManager）                   │
│  任务生命周期管理 │ 任务启停 │ 状态汇总                         │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────┬───────────▼───────────┬───────────────────────┐
│  监控模块     │      上传引擎          │       日志模块         │
│ Watcher+轮询 │  FTP客户端(线程池)      │  实时显示/落盘         │
│ 事件去抖/忽略 │  队列/重试/目录创建     │                      │
```

### 2.3 核心数据流

```
文件系统事件 ──去抖──▶ 变化文件清单 ──▶ 上传队列 ──▶ FTP 上传（含目录创建）
                                                          │
                                 成功/失败 ──▶ 日志 + 状态统计
```

## 3. 功能需求详述

### 3.1 服务器连接管理（F-01 ~ F-03）

**配置项**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 名称 | string | 连接别名 |
| 主机 | string | IP 或域名 |
| 端口 | int | 默认 21 |
| 用户名 / 密码 | string | 匿名模式可选 |
| 连接模式 | enum | 主动 / 被动（默认被动，兼容大多数 NAT/防火墙环境） |
| 字符编码 | enum | UTF-8 / GBK（影响中文文件名，见 4.6） |

**连接测试（F-02）**：使用配置发起连接并执行 `LIST` 列出根目录，成功则提示「连接成功」，失败提示具体原因（无法解析主机 / 连接被拒绝 / 认证失败 / 超时）。

### 3.2 同步任务管理（F-04 ~ F-08）

任务数据结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 唯一标识 |
| name | string | 任务名 |
| enabled | bool | 是否启用 |
| localDir | string | 本地根目录 |
| remoteDir | string | 服务器目标目录（相对路径，如 `web/assets`） |
| connName | string | 引用的服务器连接名称 |
| ignoreRules | list | 忽略规则（见 3.3） |
| deleteRemoteOnLocalDelete | bool | 本地删除是否同步删服务器（默认 false） |

- 任务启停：启用 → 建立监控并开始上传队列；停用 → 停止监控、暂停队列、断开连接。
- 新增/编辑任务时校验本地目录存在且可读。
- **立即同步（F-08）**：遍历本地目录树，按增量规则（大小+修改时间）补传。

### 3.3 实时监控（F-09 ~ F-12）

- 监听方式：对任务根目录调用 `QFileSystemWatcher::addPath`，对其下所有子目录递归注册。
  - **注意**：`QFileSystemWatcher` 只对目录变化（新建/删除/重命名子项）可靠，文件内容修改（如编辑器覆盖写入）事件可能不触发。因此采用 **Watcher + 定时扫描** 双保险（见 4.3）。
- 事件类型 → 动作映射：

| 事件 | 动作 |
| --- | --- |
| 文件新增 | 入队上传 |
| 文件修改 | 入队上传（去抖合并） |
| 目录新增 | 注册新目录监听；服务器端目录在上传时自动创建，无需立即动作 |
| 文件/目录删除 | 若 `deleteRemoteOnLocalDelete=true` 且该文件此前已上传，入队删除远端；否则仅更新本地记录 |
| 文件重命名 | 视为「新路径上传 + 旧路径按删除策略处理」 |

- 忽略规则（F-11）：支持按**完整文件名、扩展名、正则表达式**匹配；命中规则的文件不监听、不入队。默认内置忽略 `.git`、`Thumbs.db`、`*.tmp`。

### 3.4 上传引擎（F-13 ~ F-20）

- **增量判断**：记录已同步文件元数据表 `(相对路径 → 大小 + 修改时间 + MD5可选)`。监控事件触发的文件直接上传；「立即同步」场景按元数据表比对。
- **上传流程**：
  1. 从队列取文件；
  2. 确保远端目录存在（逐级 `MKD`，已存在则忽略 550 错误）；
  3. `PUT` 上传（QNAM `ftp://` 写请求）；
  4. 成功 → 更新元数据表、记日志；失败 → 记入失败队列。
- **重试（F-15）**：失败重试次数默认 3 次，间隔按 5s/15s/45s 递增（指数退避），连接级错误自动重连。重试仍失败则进入失败清单（F-24），可手动一键重试。
- **并发（F-17）**：每任务内并发上传数默认 3（可配置），通过信号槽将每个文件交给工作线程，避免阻塞 UI。
- **删除策略（F-16）**：默认关闭——本地删除文件不影响服务器，只清理本地元数据；开启后对已上传过的文件执行远端 `DELETE`。
- **校验（F-18）**：默认按文件大小比对 `LIST` 结果；可选 MD5（上传前计算本地 MD5，上传后校验）。

### 3.5 日志与状态（F-21 ~ F-24）

- 日志级别：DEBUG / INFO / WARN / ERROR，界面实时滚动显示，可按任务过滤。
- 每条日志含时间戳、任务名、文件路径、结果。
- 落盘到 `logs/app_YYYYMMDD.log`，默认保留 7 天。

### 3.6 系统集成与配置存储（F-25 ~ F-29）

- 托盘（P1）：关闭窗口时最小化到托盘而非退出；托盘菜单含「显示主界面 / 全部暂停 / 退出」。
- 配置以 QSettings 写入程序目录 `config.ini`：连接列表、任务列表、全局设置（重试次数、并发数、日志保留天数）。
- 密码安全（P1）：首版采用简单混淆存储，后续接入 Windows Credential Manager（`CredWrite` API）。

## 4. 关键技术方案

### 4.1 文件写入去抖（F-10）

大文件写入期间 `QFileSystemWatcher` 会触发多次修改事件，直接上传会读到不完整文件。

方案：每个文件维护一个去抖定时器（默认 1500ms）。事件到达后重置定时器；定时器超时后检查文件是否仍被占用（尝试以读写方式打开，或比较 1s 前后文件大小是否稳定），稳定后才入队上传。

### 4.2 Watcher + 定时扫描双保险（F-09）

由于 `QFileSystemWatcher` 对文件内容修改的可靠性有限，每任务增加一个兜底定时扫描（默认间隔 5s，可配置）：

- 遍历本地目录树，与已同步元数据表比对，发现大小/修改时间变化或新增文件 → 入队上传；
- 该机制同时保证程序启动后、暂停恢复后的一致性与监控遗漏兜底。

### 4.3 FTP 客户端设计

- 基于 `QNetworkAccessManager` 的 `ftp://` 请求，封装 `FtpClient` 类：
  - `list(path)`、`mkdir(path)`、`put(remotePath, localFile)`、`del(path)`；
  - 提供 `put` 的 `uploadProgress` 信号用于进度展示（P1）。
- **限制与对策**：QNAM FTP 不支持重命名远端文件，故重命名事件采用「新路径上传 + 旧路径按删除策略删除」。
- 每个任务持有一个专用 `QNetworkAccessManager`，避免跨任务串扰；断线后自动重建连接。

### 4.4 多线程与 UI 安全

- 上传工作放于每任务独立的工作线程；与 UI 的通信一律通过信号槽（跨线程自动排队）。
- 日志、状态、进度均通过信号发往 UI 线程更新，杜绝直接操作控件。

### 4.5 配置与元数据存储

- `config.ini`：服务器连接、任务、全局设置。
- `sync_meta.json`（每任务一个）：已同步文件元数据表。保存时机：文件上传成功后增量更新；任务停用/程序退出时落盘。

### 4.6 中文文件名处理

- FTP 中文文件名易乱码。方案：连接配置提供「字符编码」选项（UTF-8 / GBK），上传路径与 LIST 解析均按所选编码处理；QNAM FTP 默认按 UTF-8 处理，GBK 场景需在路径字节层面处理（若 QNAM 不满足，回退方案见 4.7）。

### 4.7 风险预案：QNAM FTP 能力不足

若评审中发现 QNAM FTP 无法满足需求（如编码、LIST 解析、目录创建语义），回退方案：基于 `QTcpSocket` 自行实现精简 FTP 客户端（控制连接命令 + 数据连接被动模式），只实现 LIST/MKD/PUT/DELETE/REST，工作量可控且可控性最高。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 单任务 100 个 1MB 以下文件连续变化，去抖后上传队列不堆积；并发上传不阻塞 UI |
| 可靠性 | 上传失败自动重试；程序异常退出后重启可恢复任务状态，不重复上传已成功文件 |
| 可用性 | 界面操作 1 分钟内上手；关键操作有明确提示与确认 |
| 安全 | 密码不明文存储；不支持加密传输属已知限制（仅 FTP），在文档与界面中明示 |
| 兼容性 | 支持 Windows 7 SP1 / 10 / 11（32/64 位均可，当前工程为 32 位构建） |

## 6. 界面设计（概要）

```
┌────────────────────────────────────────────────────────┐
│ 标题栏：自动同步文件到 FTP 服务器                 [托盘] │
├────────────────┬───────────────────────────────────────┤
│  导航（左侧）    │           内容区（右侧）                │
│  ● 服务器配置    │   [服务器连接表单/列表]                 │
│  ● 同步任务      │   [任务列表 + 新增/编辑任务对话框]       │
│  ● 日志          │   [实时日志/传输统计]                  │
├────────────────┴───────────────────────────────────────┤
│ 状态栏：任务运行状态 │ 已上传 N 个 │ 失败 M 个 │ 最近同步 xx │
└────────────────────────────────────────────────────────┘
```

页面构成：
1. **服务器配置页**：连接列表 + 表单 + 「测试连接」按钮。
2. **同步任务页**：任务卡片/表格（状态、最近同步时间、上传计数），操作：启用/停用、立即同步、编辑、删除。
3. **日志页**：过滤条件（任务、级别）+ 实时日志滚动区 + 失败清单（一键重试）。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| QNAM FTP 能力不足（编码/语义） | 中文文件名或目录创建异常 | 提前做技术验证；预案：自研精简 FTP 客户端（4.7） |
| 文件监听漏报 | 文件未及时上传 | Watcher + 定时扫描双保险（4.2） |
| 大文件上传被中断 | 服务器残留半文件 | REST 断点续传（P2）+ 上传临时文件名策略（上传 `.uploading` 临时文件，完成后再重命名为目标名） |
| 监控高频变化导致队列膨胀 | 上传积压、带宽占用 | 去抖合并 + 队列上限 + 并发控制 |
